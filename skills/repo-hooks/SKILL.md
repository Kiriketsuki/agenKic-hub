## Context

Claude Code hooks in `settings.json` run globally. But different repos need different
lint/check commands. This skill detects the repo's language stack and writes a single
PostToolUse hook script that dispatches the right checker based on the edited file's
extension. The script lives in the repo itself (`.claude/hooks/repo-lint.sh`) and is
added to `settings.json` as a PostToolUse hook on `Edit|Write`.

The hook runs after every Edit or Write, checks if the edited file matches a known
language, and runs the appropriate checker. Non-zero exit blocks the edit with feedback.

## Triggers

- "setup hooks for this repo"
- "add repo hooks"
- "configure linting hooks"
- `/repo-hooks`

## Workflow

### Step 1 -- Detect Languages

Scan the repo root for language indicators:

| Indicator | Language | Check Command |
|:---|:---|:---|
| `tsconfig.json` or `*.ts` files | TypeScript | `npx tsc --noEmit` |
| `go.mod` | Go | `go vet ./...` |
| `*.py` files + `pyproject.toml` or `requirements.txt` | Python | `python -m py_compile "$FILE"` |
| `Cargo.toml` | Rust | `cargo check` |
| `package.json` (no tsconfig) | JavaScript | `npx eslint "$FILE" --no-error-on-unmatched-pattern` (if eslint configured) |

Report what was detected: "Found: TypeScript, Python. No Go, Rust, or JS-only detected."

### Step 2 -- Generate Hook Script

Create `.claude/hooks/repo-lint.sh` in the repo root:

```bash
#!/usr/bin/env bash
# Auto-generated by /repo-hooks -- repo-specific lint after Edit/Write
# Re-run /repo-hooks to regenerate if the stack changes.

set -euo pipefail

FILE="${CLAUDE_TOOL_ARG_file_path:-${CLAUDE_TOOL_ARG_filePath:-}}"
[ -z "$FILE" ] && exit 0

REPO_ROOT="$(git -C "$(dirname "$FILE")" rev-parse --show-toplevel 2>/dev/null || echo "")"
[ -z "$REPO_ROOT" ] && exit 0

# Only check files inside this repo
case "$FILE" in "$REPO_ROOT"/*) ;; *) exit 0 ;; esac

cd "$REPO_ROOT"

case "$FILE" in
[LANGUAGE_CASES]
esac
```

Replace `[LANGUAGE_CASES]` with the detected languages. Example for TypeScript + Python:

```bash
  *.ts|*.tsx)
    npx tsc --noEmit 2>&1 | head -20
    ;;
  *.py)
    python -m py_compile "$FILE" 2>&1
    ;;
```

Make it executable: `chmod +x .claude/hooks/repo-lint.sh`

### Step 3 -- Register in settings.json

Check if a repo-lint hook already exists in `settings.json` PostToolUse > Edit|Write.
If not, add it. The command should use the absolute path to the script:

```json
{
  "type": "command",
  "command": "bash <REPO_ROOT>/.claude/hooks/repo-lint.sh"
}
```

Use the `/update-config` skill or edit `settings.json` directly.

**Important**: This adds a repo-specific path to the global settings. If the user works
across many repos, consider noting that the hook will only fire for files inside that repo
(the script's `case "$FILE"` guard handles this).

### Step 4 -- Test

Run a quick smoke test:
1. Pick a source file in the repo
2. Simulate the hook by running the script with `CLAUDE_TOOL_ARG_file_path` set
3. Report: "Hook test passed -- [language] checker ran cleanly." or report errors

### Step 5 -- Report

```
Repo hooks configured for: [languages]
Script: <REPO_ROOT>/.claude/hooks/repo-lint.sh
Registered in: settings.json PostToolUse > Edit|Write

Checks that will run after edits:
- *.ts/*.tsx -> npx tsc --noEmit
- *.py -> python -m py_compile
```

## Edge Cases

- **Monorepo with multiple languages**: Include all detected case branches
- **No known languages detected**: Report "No supported languages found" and exit
- **Hook already exists**: Read existing script, show diff, ask before overwriting
- **eslint not configured**: Skip JS linting rather than installing eslint
- **Go modules outside repo root**: Use `go vet ./...` from the module root, not file dir

## Removal

To remove repo hooks:
1. Delete `.claude/hooks/repo-lint.sh` from the repo
2. Remove the corresponding entry from `settings.json`
